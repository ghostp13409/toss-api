# Feature Requirements Document: Scripting Engine (Pre-Request & Post-Response)

---

## 1. Feature Overview

The Scripting Engine allows users to execute dynamic code before an HTTP request is dispatched (**Pre-Request Scripts**) and immediately after a response is received (**Post-Response / Test Scripts**). This feature brings Postman-style automation—such as dynamic token generation, signature calculation, assertions, and variable chaining—directly into a modal, terminal-driven environment.

---

## 2. Core Functional Requirements

### 2.1 Script Execution Lifecycle

* **Pre-Request Script Execution:** The app must run the pre-request script prior to constructing the final HTTP payload and sending the request to the target server.
* **Post-Response Script Execution:** The app must run the post-response script immediately after receiving the response headers and body, before rendering the final response view in the UI.
* **Asynchronous Execution & Timeout:**
* Script execution must run asynchronously or in an isolated worker context to prevent freezing the TUI main thread.
* The user must be able to configure a maximum script execution timeout (e.g., default `5000ms`). If a script exceeds this, execution must abort with a clear error overlay.



---

### 2.2 Global API Object & Environment Interaction

The scripting environment must expose a dedicated runtime API object (e.g., `client` or `pm`) allowing scripts to read and manipulate application state.

* **Variable Manipulation:**
* **Read Variables:** Users must be able to retrieve variables across scopes: `client.variables.get("var_name")`, `client.environment.get("var_name")`, and `client.globals.get("var_name")`.
* **Write/Set Variables:** Users must be able to dynamically set or update variables: `client.environment.set("token", "xyz")` or `client.globals.set("user_id", 123)`.
* **Unset/Clear Variables:** Users must be able to delete variables programmatically: `client.environment.unset("temp_key")`.


* **Request Object Access & Mutation (Pre-Request):**
* Read and modify the targeted URL, HTTP method, request headers, query parameters, and raw request body.
* Dynamically append or override headers (e.g., set an dynamic `Authorization` or `X-Signature` header computed inside the script).


* **Response Object Access (Post-Response):**
* Read the response HTTP status code (e.g., `response.status === 200`).
* Access response headers and payload size.
* Parse response bodies natively via built-in utilities (e.g., `response.json()` or `response.text()`).



---

### 2.3 Assertions & Testing Framework

* **Test Case Definition:** Users must be able to define named test cases (e.g., `client.test("Status code is 200", function() { ... })`).
* **Assertion Engine:** Provide standard assertion utilities (e.g., `client.expect(response.status).to.equal(200)` or `client.expect(data.id).to.exist`).
* **Test Results UI View:**
* The UI must display a dedicated **Test Results** tab or summary panel in the Response inspector.
* Show pass/fail status, total passed/failed count, and failure reason for each defined test.



---

### 2.4 Built-in Libraries & Utilities

To support common cryptography and data manipulation tasks without requiring external network fetches, the runtime context must include standard built-in modules:

* **Crypto Utilities:**
* Hashing algorithms: `MD5`, `SHA-1`, `SHA-256`, `SHA-512`.
* HMAC signatures (e.g., `Crypto.hmacSha256(message, secret)`).
* Encoding/Decoding: `Base64` and `URL` encoding functions.


* **Data Parsing:** Native support for `JSON.parse()` / `JSON.stringify()`.
* **Utility Generators:** Built-in dynamic data generators accessible via script (UUID v4, ISO timestamps, random integers, random strings).

---

### 2.5 Console Logging & TUI Debugger

* **In-App Script Console:** Users must be able to view logs generated by scripts via `console.log()`, `console.warn()`, and `console.error()`.
* **Dedicated Debug Pane:**
* Provide a toggleable TUI log viewer panel (e.g., accessible via keybinding or command palette).
* Timestamps and log level highlighting for debugging failed pre-request/post-response logic.



---

## 3. TUI Workflows & Editor Interface

* **Modal Script Editor:**
* Dedicated tabs within the Request Panel for `Pre-Request Script` and `Tests / Post-Script`.
* Embedded multi-line editor mode with syntax highlighting for JavaScript/Lua.


* **Snippet Presets:**
* Quick-insert code templates via command palette or dropdown menu (e.g., "Set an environment variable", "Check status code 200", "Parse JSON response body", "Generate HMAC signature").
